【一句话介绍】
神经元式智能体工作流可视化平台。
前端 React 18 + TypeScript + Vite 5173（工作台 UI + 神经元动效引擎），
后端 Python FastAPI 8000（动态拓扑 DAG 编排引擎 + WebSocket 遥测 + 工件发布）。
设计语言："赛博蜘蛛 HUD + 道家哲学叙事"，前后端共用同一套数据契约 1:1 对接。

══════════════════════════════════════════════════════════════════════
零、先看这五条（30 秒版）
══════════════════════════════════════════════════════════════════════
  1. 前端入口就一层皮：main.tsx(11行) → App.tsx(5行) → Workbench.tsx(964行)。
     Workbench 是前端唯一的状态中枢，所有面板/画布由它挂载和喂数据。
  2. 后端主用的是带 perfect 前缀的 perfect_main.py + perfect_engine.py
     （v2.8）；不带前缀的 main.py + engine.py 是 v1 旧版，保留兼容。
  3. 前后端通信：REST 15 个接口（/api/v1/*）+ WebSocket 1 条通道
     （/ws/telemetry，4 种事件）。数据格式全部由 backend/models.py 定义。
  4. 后端核心是一个 DAG 执行引擎：节点按拓扑分层，逐层执行，每个节点
     的实际动作由"算子注册表"里的 12 个算子 + 1 个兜底承担（画布节点 type 经别名表归一化）。
  5. frontend 里带 Neural 前缀的 5 个备件组件（WebGL着色器/小地图/声效/
     备选画布/后端Hook）没有被 Workbench import，未接线不生效。

    class ConnectionManager        WebSocket 连接管理

    class PerfectNeuralEngine      核心引擎
      _init_components()          初始化组件库
      _init_nodes()               初始化默认工作流节点
      _init_edges()               初始化默认突触连线

  ▍operator_registry.py ★算子注册表（节点动作的分发中心）
    _ALIASES                      画布节点 type → 算子 key 别名归一化表
                                  （event_capturer→trig_events 等 5 条）
    class NeuralOperatorRegistry
      execute(key, cfg, bus, inputs=None)
                                  key 先经 _ALIASES 归一化；上游输出注入
                                  cfg 副本 _inputs；返回值带 operator 与
                                  mode:"simulated"（如实标注内置模拟）
      12 个算子 + 1 个兜底，三段式命名 <阶段>_<动作>：
        触发  trig_events      事件触发
              trig_schedule    定时触发
        感知  perc_nlu         自然语言理解
              perc_vision      视觉感知
        智能体 agent_intent   意图识别
               agent_codegen  代码生成
        逻辑  logic_transform 数据变换
              logic_state     状态管理
        前端  fe_assemble     前端组装
              fe_render       前端渲染
        部署  dep_test        测试
              dep_publish     发布
        兜底  default         未知类型兜底
      每个算子签名：async _op_xxx(cfg, bus) -> Dict（cfg 节点配置，
      bus 总线：节点间传递的数据；cfg["_inputs"] 为上游输出）

五、一次完整交互的数据流（举例：用户拖拽加节点）
══════════════════════════════════════════════════════════════════════
    1. 用户在侧边栏点一个组件卡
    2. Workbench 调 POST /api/v1/workflow/nodes
    3. perfect_main → PerfectNeuralEngine.add_custom_node_from_sidebar()
       生成节点、compile_topological_layers() 重算分层
    4. 引擎 broadcast "workflow_snapshot" → 前端重绘画布
    5. _dag_execution_loop() 执行该节点 → _execute_single_node()
       → operator_registry.execute(type) 走对应算子
    6. 执行中 broadcast "node_update"（进度）和 "terminal_log"（日志）
    7. _telemetry_loop() 周期 broadcast "telemetry_tick"
       → Workbench 顶栏示波器实时跳动
    8. CheckpointStore.save_checkpoint() 存 SQLite → 时间旅行弹窗可恢复

    AIGENT_DB_PATH            SQLite 断点库路径
    AIGENT_PERSIST_TOPOLOGY   =1 启动时还原并持久化拓扑（默认 1）
    CHECKPOINT_MAX            断点库上限（默认 2000，超出剪枝）
    VITE_API_BASE             前端 REST 基址（默认 http://localhost:8000/api/v1）
    VITE_WS_URL               前端 WS 地址（默认 ws://localhost:8000/ws/telemetry）

九、给看的人的三个提示
══════════════════════════════════════════════════════════════════════
    1. 找功能先认"前缀"：后端 perfect_* 是现役（v2.8），不带 perfect 的

       前端 Workbench.tsx 里的 interface 是它的镜像。

       12 个算子 + 1 个兜底就是所有节点动作的完整清单。
